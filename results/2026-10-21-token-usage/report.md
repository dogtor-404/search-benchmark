# 两轮测试与Codex自身用量估算

统计截点：北京时间2026年10月21日10:29:40，用户要求将Codex自身用量计入之前。

**主口径合计约3.16亿～3.20亿 token。**

| 部分 | 累计token约数 |
|---|---:|
| 两轮2200份正式作答，含已上报搜索辅助模型 | 42.7～47.0百万 |
| 第一轮2000次API判分 | 7.5百万 |
| 两轮Codex主对话：执行、开发、分析、整理等 | 165.9百万 |
| 11个Codex评分/复核agent | 100.0百万 |
| 合计 | 316.1～320.3百万 |

Codex自身合计约2.66亿，其中缓存读取约2.61亿；缓存占Codex输入的98.4%。这解释了为何加入主agent后比仅作答/判分的五千多万高很多。

这统计的是模型累计处理量，包括长上下文的多轮重复读取。不能说成“新生成了三亿token”，也不能按同等全价token直接换算现金。缓存是输入的一部分，推理token是输出的一部分，没有重复相加；参照 [OpenAI Docs：Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)。

只纳入两轮主任务及其评分/复核agent。同一项目的其他独立对话及后台辅助审查另列，不混入主口径；若连这些可见记录一起计入，约3.42亿～3.46亿。

试跑、失败重试、搜索服务内部未上报token未完整汇总。删题后的92/95题只是评分分母，已运行的2200份作答消耗没有扣回。不是账户账单，也不包含统计截点之后本轮核算继续发生的token。
