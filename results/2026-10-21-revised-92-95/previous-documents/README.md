## 当前统一计分规则与原因

第一轮和小语种第二轮的全部十组使用同一规则：答对一道题 **+5分**；答错且仍提交答案 **−3分**；不答、说明不知道，或先给候选但最终撤回答案，作答分均为 **0分**。第一次搜索不扣分，从第二次起每多搜一次 **−1分**，对答对、答错和弃答都生效，不设0分下限。

**每题得分 = 作答分 − max（搜索次数−1，0）。** 例如搜索3次后，答对得+3，答错得−5，不答或最终撤回得−2。“可能/不确定但仍提交”仍按最终答案的对错计分；只有最终不回答或撤回才归0，不因加一句免责声明自动免除错答扣分。

为什么这样打分：

- **看最终回答，不按关键词命中给分。** 本测试把搜索视为模型作答的次生能力：模型需要理解问题、组织查询、判断返回内容是否在正确的上下文里支持答案，再决定如何回答。搜到关键词或在回答中碰巧提到标准答案，如果上下文与问题不符，不能像传统搜索引擎的关键词命中那样直接得分。
- **弃答与最终撤回同记0。** 无论一开始说不知道，还是试猜后明确撤回，最终都没有交付可采纳的答案；不能因为曾经说出某个答案或关键词而奖励，也不按一次已提交的错答处罚。实际发生的额外搜索成本仍另扣。
- **错误回答记负分。** 幻觉或错误答案可能误导使用者，对最终结果造成伤害，因此提交错误答案得−3分；它与坦承不知道的0分有实质区别。本指标按答案是否错误计罚，不要求证明模型有意编造，也不把所有错误都命名为幻觉。
- **额外搜索扣分，计入时间和资源成本。** 多次搜索可能反映问题理解、查询组织或检索能力出现困难，也会消耗更多时间与资源，所以从第二次起每次扣1分；首次查询保留为正常的工具使用成本。搜索次数是本测试采用的效率信号，也可能来自必要核验，不能单凭一次多搜就断定模型能力失败。

这是查看原结果后由用户统一确定的事后综合指标。旧正确率和旧100分制搜索扣分表保留供回查；它们不再代表当前统一计分。第一轮当前主表采用已有的96题统一排除口径，原100题视图另保留；小语种第二轮仍为120题，不合并两轮总分作模型总排名。

## 要回答的问题

1. **给 Claude 用，哪家的搜索更好**：DeepSeek 的 Search API，还是 Claude Code 自带的 WebSearch？
2. **DeepSeek 的搜索更适合配哪个模型**：Claude 还是 DeepSeek？
3. **模型越强，是不是越会用搜索**：中档模型和高档模型，从同一个搜索里多拿到的分一样吗？

## 背景（2026-10-20 查的）

**Claude Code 的 WebSearch**
- 不在本机跑：它调用 Anthropic API 的服务端 `web_search` 工具，由 Anthropic 去搜，再把结果交给模型。底层用哪家搜索引擎，官方没公开。
- 价格：走 API 是每 1000 次 10 美元，搜回来的内容另按输入 token 计费；用 Pro / Max 订阅登录时不按次收费，算进订阅的 5 小时额度和每周额度。
- 搜回来的网页内容是加密的（`encrypted_content`），只有 Claude 模型能读，别的模型只拿得到标题和链接。Claude Code 交给主模型的是一串链接，加一段模型写的摘要。

**DeepSeek 的 Search / Fetch API**
- 2026-10-17 上线，用的是 DeepSeek 自己的搜索引擎。接口是 `POST https://api.deepseek.com/v1/tools/search` 和 `.../v1/tools/fetch`，和 DeepSeek 的模型 API 用同一个 key。
- 价格：每 1000 次成功请求 0.75 美元；失败、结果为空、超时都不收钱。限流：Search 每秒 100 次，Fetch 每秒 25 次，按账号算。
- 每条结果带 `snippet`（100–200 字，给界面显示）、`summary`（600–800 字，给模型读）、`rerank_score`（0–3，1.5 以上算高质量）、`authority`（0–4，3 以上算权威）、`date`。
- 免费期：通过 DeepSeek Harness、Claude Code、Codex 连 DeepSeek API 时，由服务端发起的搜索在北京时间 2026-11-01 00:00 前免费。**本测试直接调用 Search API，不在免费范围内。**

**已有的评测**
- 截至 10-20，没有任何独立评测比过这两家的搜索。主流的搜索 API 评测（SimpleQA、Artificial Analysis 9 月的 Search Index、AIMultiple）两家都没收录。
- BrowseComp 榜上有两家模型的分数（Claude Opus 5 90.8%，DeepSeek V4 Pro 0813 83.4%），但测的是“模型 + 搜索”的整体，分数多是各家自报，比不出搜索本身好坏。
- 唯一一篇实测 DeepSeek 搜索的（Suganthan，10-17），测的是它怎么排序、怎么打分，没测答案对不对。

- 档次照 DeepSeek 自己的映射来配：它把 claude-sonnet、claude-haiku 映射到 deepseek-flash，把 claude-opus 映射到 deepseek-v4-pro。
- `deepseek-flash` 从 10-17 起背后是 DeepSeek-V4.1-Flash-1017。这个名字会随 DeepSeek 升级换成新模型，所以十组要一次跑完，报告里记下跑的日期和模型版本。
- B、D2、B′、D2′ 用的是同一个 DeepSeek 搜索工具（见“每组怎么跑”）。

## 怎么比

- **问题 1**：A 对 B，A′ 对 B′，直接比答对率。两边是同一个 Claude，它本来就知道的那部分两边一样多，不需要对照组。
- **问题 2**：B − 0 对 D2 − D0，B′ − 0′ 对 D2′ − D0′。0 和 D0 是对照组（不搜，看模型本来就知道多少），减掉以后剩下的是“靠搜索多答对的题”。哪个提升值大，DeepSeek 的搜索就更适合配那个模型。
- **问题 3**：在同一个模型系列内，比高档和中档的提升值：B′ − 0′ 对 B − 0，D2′ − D0′ 对 D2 − D0，A′ − 0′ 对 A − 0。

## 为什么这样设计（决定记录）

- **固定模型、只换搜索**：这样答对率的差别才能算到搜索头上。
- **取消“DeepSeek 模型 + Claude 搜索”（原来的 D1）**：Claude 的搜索结果是加密的，DeepSeek 读不了，只能让一个 Claude 当中间人，读完结果再写摘要交给 DeepSeek，这样测的就不是 DeepSeek 了。所以 Claude 的搜索只在 Claude 模型的组里比。
- **全部放在 Claude Code 里跑，B 和 D2 用同一个工具**：两组只差模型这一样。dsh、Codex 不比，那比的是 harness，不是这次要回答的问题。
- **加对照组**：Claude 赢了，也可能只是它本来就记得答案。
- **两边档次对齐**：拿 Opus 去比 flash，Claude 会吃档次的便宜。
- **全部关掉抓网页**：只靠搜索结果作答，比的是搜索本身。
- **等周额度重置再跑**：10-20 那天 Max 的周额度只剩 15%，一天后重置。Claude 那六组都扣这份额度，要等重置以后先试跑。
- **题目用公开题集加自己的题（10-20）**：先看了别人的评测（见 已有项目调研.md（材料保留于本地）），只挑在“只靠搜索、最多搜 5 次”的条件下答得出来的题集。
- **自己搭，不用 Exa 的 Scout（10-20 定）**：在 Claude Code 里跑，Claude 那几组扣订阅额度，A 组测的就是日常用的那个 WebSearch。判分、bootstrap 区间、成本记录这些自己写，写法可以参考 Scout（`harness/statistics.py` 等）。

## 题目（100 道，每道都有标准答案和来源）

公开题集和我们自己的题各一半左右：公开的那部分能和别人的结果对得上，自己的题补上中文和新闻这两块空白。中文题大约占一半。

| 题集 | 数量 | 语言 | 类型 | 授权 |
|---|---|---|---|---|
| [SimpleQA Verified](https://huggingface.co/datasets/google/simpleqa-verified)（Google DeepMind） | 25 | 英文 | 一步就能查到的事实 | MIT |
| [Chinese SimpleQA](https://huggingface.co/datasets/OpenStellarTeam/Chinese-SimpleQA)（淘天团队） | 25 | 中文 | 一步就能查到的事实 | CC BY-NC-SA 4.0 |
| [FRAMES](https://huggingface.co/datasets/google/frames-benchmark)（Google） | 15 | 英文 | 多跳，只挑需要两三步的 | Apache-2.0 |
| 我们自己的 | 25 | 以中文为主 | 从各部视频的 `docs/01-研究笔记.md` 里挑有两个以上来源、答案短而确定的事实，多挑只在中文网页上有的（B 站、知乎、中文报道）。不碰 `[PRIVATE_SOURCE_DIR]` | — |
| 新闻 | 10 | 中英文 | 跑测试前最近一个月（30 天）内的事；不要求晚于模型训练截止日期，答案和来源在出题时当场核实 | — |

- 公开题集用固定的随机种子抽题（种子写进 `questions/README.md`），别人可以复现。抽出来的题先人工过一遍，把答案已经过时的剔掉，再按原顺序补抽。
- FRAMES 每道题标了要读几篇 Wikipedia 文章，只从需要两三篇的题里抽。
- 公开题集出得早（2024–2025 年），模型很可能训练时见过，不搜的对照组就是用来量这个的。自有题和新闻题补充公开题集的覆盖范围；不保证模型训练时未见过，仍通过不搜的对照组衡量模型原有知识。
- Chinese SimpleQA 是 CC BY-NC-SA 授权：自己测没问题；以后如果公开题目，或者在视频里引用题目，要署名，用同样的协议，而且不能商用。

**不用的题集**
- BrowseComp、BrowseComp-ZH：要连着翻好多网页。在“最多搜 5 次、不抓网页”的条件下，所有组都会接近 0 分，比不出差别；BrowseComp-ZH 的仓库也没写授权协议。以后要是给两边配同一个抓网页的工具，再把它们加回来。
- AA-Omniscience：不公开，拿不到。

题目存在 `questions/questions.jsonl`，每行一道：`id`、`set`、`lang`、`question`、`answer`、`aliases`（也算对的写法）、`source_urls`（正确来源）。

## 每组怎么跑

**所有组都一样的设置**
- `claude -p --output-format stream-json --verbose --no-session-persistence --model <模型>`，在本目录里跑。不要在 `[PRIVATE_SOURCE_DIR]` 里跑，那里会加载视频工作区的 CLAUDE.md 和 SessionStart hook。
- 加 `--setting-sources project,local`，不加载用户级设置：`~/.claude/settings.json` 里有很多 hook，会让各组跑的条件不一样。（`--bare` 不能用：它只认 `ANTHROPIC_API_KEY`，订阅登录用不了。）
- 一道题单独跑一次，原始输出（stream-json）存到 `tmp/archive/jsonl/<组>/<题号>.jsonl`，存放规则见下面“结果怎么存”。
- 提示词：
  - 有搜索的组：“用搜索回答下面的问题。给出简短的答案和你依据的网址。最多搜 5 次。”
  - 不搜的组：“不能上网，凭你知道的回答；不知道就说不知道。”

**各组的工具**
- **A / A′**：`--tools WebSearch`，只开搜索，WebFetch 关掉。
- **B / D2 / B′ / D2′**：`--tools ""` 关掉所有自带工具，用 `--mcp-config tools/deepseek-search.json --strict-mcp-config` 接 DeepSeek 搜索工具。这个工具每次调 Search API 时 `count=10`、`need_content=false`，返回每条结果的标题、网址、snippet、summary、日期；它自己记次数，超过 5 次就拒绝。
- **0 / D0 / 0′ / D0′**：`--tools ""` 加 `--strict-mcp-config`，什么工具都没有。

**DeepSeek 模型那几组（D0、D2、D0′、D2′）**
- 环境变量只给这一条命令设：`ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`，`ANTHROPIC_AUTH_TOKEN="$(security find-generic-password -s DEEPSEEK_API_KEY -w)"`，`--model deepseek-flash` 或 `--model deepseek-v4-pro`。
- key 只从钥匙串里读，不写进任何文件，也不打印出来。

**没法完全对齐的地方**：Claude 的 WebSearch 一次返回几条结果，我们控制不了，只能记下实际条数；DeepSeek 固定 10 条。

## 指标

1. **答对率**：判分时让两个模型（一个 Claude，一个 DeepSeek）对照标准答案判，都不告诉它们答案是哪一组的。两个判分模型意见不一致的、或者拿不准的，人工看。
2. **来源命中率**：正确来源有没有出现在模型拿到的前 5 条搜索结果里。只算有搜索的组。这一项受模型影响最小，最能直接反映搜索本身。
3. **搜索次数和耗时**：平均搜几次才找到答案，每道题花多长时间。
4. **错误类型**：没搜到、搜到了过时的页面、混进了垃圾页、搜到了但读错了、模型自己编的。

## 统计

- 所有组都用同一批题，配对比较：A 对 B 用 McNemar 检验；提升值之间的差（问题 2、3）用 bootstrap 按题重抽样，算 95% 区间。
- 100 道题只看得出大差别：答对率要差 10 个百分点左右才可信；提升值之间的差误差更大，要差 15 个百分点以上。区间跨过 0，就写“看不出区别”。

## 成本和时间

- **DeepSeek 搜索费**：B、D2、B′、D2′ 四组，每组约 300 次，一共约 1200 次，不到 1 美元。
- **DeepSeek 模型 token**：flash 很便宜，v4-pro 贵一些，试跑时量出来。
- **Claude**：六组一共 600 次运行，扣 Max 20x 的订阅额度（5 小时额度和每周额度），不花现金。Opus 那三组最费额度。
- **先试跑**：每组跑 10 道题，量出每次运行的花费和耗时，再推算全量。跑之前用 `/status` 看还剩多少周额度；不够就把题目减到 60 道，或者分两周跑（但 `deepseek-flash` 可能中途换模型，见上）。
- **时间**：全程自动跑，可以并行，几个小时。

## 局限

- 测的是在 Claude Code 里的表现，换到 dsh 或 Codex，结果可能不一样。
- 关掉了抓网页：实际做研究时模型还会去读原文，这次只比搜索结果本身。
- 两边都隔着一层摘要：Claude 的 WebSearch 自带一段模型写的摘要，DeepSeek 的结果自带 `summary` 字段，但写摘要的不是同一个模型。
- 题目大多是查事实，不代表长篇调研的表现。

## 结果怎么存（为开源做准备）

这个测试以后要开源，所以原始输出不删，全部留下来，开源前统一检查。

1. **跑的时候**：全部写进 `tmp/archive/jsonl/`。
   - `tmp/archive/jsonl/<组>/<题号>.jsonl`：每次运行的原始输出（`claude -p` 的 stream-json）。
   - `tmp/archive/jsonl/grades/<判分模型>.jsonl`：判分结果，一行一道题一组。
   - `tmp/archive/manifest.json`：复现要用的信息，包括跑的日期、Claude Code 版本、每组的模型名（`deepseek-flash` 写明背后是哪一版）、提示词全文、随机种子、`questions.jsonl` 的哈希。
2. **全部跑完再移动**：十组都跑完、判分也做完以后，把 `tmp/archive/` 整个移到 `results/<跑的日期>/`。跑到一半的、失败要重跑的，都留在 `tmp/` 里，不要先移。
3. **试跑不算**：每组 10 道题的试跑，输出放 `tmp/pilot/`，不移动，也不公开。
4. `tmp/` 不进 git（`.gitignore` 里要有 `tmp/`）。

## 开源前检查（移进 `results/` 之后、公开之前）

- **没有密钥**：DeepSeek 的 key、Claude 的登录凭据、任何 token。用 `sk-`、`Bearer`、`token` 之类的关键词搜一遍。
- **没有个人信息**：本机路径（`/Users/<用户名>` 改成 `~`）、用户名、邮箱、账号和组织名。`claude -p` 每次输出开头的初始化信息里会列出本机的工具、插件、MCP 服务器，这部分整段删掉，只留模型名和这次开的工具。
- **授权分两份（10-20 定）**：
  - **代码**（`tools/`、脚本）用 MIT。
  - **数据**（`questions/`、`results/`）统一用 CC BY-NC-SA 4.0。原因是 Chinese SimpleQA 是 CC BY-NC-SA，“相同方式共享”这一条要求凡是包含它题目的东西都用同样的授权，原始输出里也有题目原文。
  - SimpleQA Verified（MIT）和 FRAMES（Apache-2.0）是宽松授权，可以并进数据部分，但要保留它们原来的出处和授权说明。
  - 仓库根目录放 `LICENSE`（MIT，管代码）；`questions/` 和 `results/` 各放一份 `LICENSE`（CC BY-NC-SA 4.0），再加一份 `NOTICE`，列出每个题集的出处和原授权。
- **我们自己的题**：只能用已经发布的视频的研究笔记出题，免得把还没发布的选题露出去；拿不准的问用户。
- **搜索结果里的网页摘录**：原始输出里有大量第三方网页的摘录。公开时是全文保留，还是只留标题和网址，开源检查时由用户决定。

## 步骤

1. 建题库，核实每道题的标准答案和来源。
2. 写 DeepSeek 搜索工具和跑测试的脚本。
3. 试跑：每组 10 道题，输出放 `tmp/pilot/`，看工具和判分都正常，量出花费。
4. 跑全量，输出写进 `tmp/archive/jsonl/`。
5. 判分，人工复核两个判分模型意见不一致的题。
6. 全部跑完、判完，把 `tmp/archive/` 移到 `results/<跑的日期>/`。
7. 写 `report.md`：每组的数字、95% 区间，再加十来个典型例子（各自答对、答错的题）。
8. 开源前检查（见上面那一节），用户确认后再公开。

## 第二轮：多语种档（10-21 定）

正式轮评分更新（用户后续指示）：以下原计划三票规则保留为历史方案；实际正式轮采用独立AI单票盲评，每份仅一票，取消两位API判分员。前1100份以100条批次发布，末100份分5个20条不可变匿名包，盲评与作答并行；待核不当错题，作答设计保持原样。

执行状态（2026-10-21）：120题题库已冻结，十组各6题共60份试跑及三位AI共180票全部完成，试跑多数票待核0份；试跑仅检查流程，不作排名。试跑报告（本地材料，不随公开副本发布）、运行检查与费用（本地材料，不随公开副本发布）、评分分歧（本地材料，不随公开副本发布）。用户批准全量后，十组各120题共1200份有效作答及1200张独立AI单票盲评现已全部完成，18份待核保留；正式轮没有调用Claude/DeepSeek评分。结果已归档至 正式报告（材料保留于本地）、搜索次数与扣分（材料保留于本地）、逐题查询与返回摘要（材料保留于本地）。用户运行中新增的额外每次搜索扣5分另报，保留原正确率；试跑三票记录不变。冻结配置、1200个唯一评分ID、6339个归档文件与1200条CLI版本记录核验通过；原始记录及两次技术故障归档均保留。按实测时段和公开单价估值约$3.74，含已知无效次模型及成功搜索，不是账单，不含既有订阅费。

**为什么加这一轮**：第一轮有搜索的六组都在 91–99%，题太简单，撞到了天花板，比不出两家搜索谁更强；题目又只有中文和英文。DeepSeek 用的是自建索引，中文、英文以外的语言覆盖得怎么样，没人测过，两家最可能分出高下的就是这里。MSQA 论文里，模型不搜平均只答对 21%，加了搜索也只到 26%，说明这些题既难记也难搜，不容易再撞天花板。

**题目：120 道，来自 [MSQA](https://huggingface.co/datasets/m-a-p/MSQA)**
- MSQA 是字节 Seed、M-A-P 等 2026 年 7 月发布的（[论文](https://arxiv.org/html/2607.00724v3)），CC BY 4.0 授权，共 1064 道。题目由母语者根据本国资料出，不是从英文翻译的；答案短而唯一，每道题都附来源网址。
- 挑 6 种网络生态差别大的语言，每种 20 道：日语、韩语、泰语、印尼语、俄语、西班牙语。MSQA 里中文和英文的题不用，第一轮已经有了。
- 每种语言用固定的随机种子分层抽题，种子写进 `questions/README.md`。抽出来先用 AI 过一遍，剔除答案会随时间变化的、题意有歧义的、来源网址失效的，再按原顺序补抽。剔除原因逐题记录。
- 题目保留原文，不翻译；`lang` 字段写语言代码（`ja`、`ko`、`th`、`id`、`ru`、`es`）。存成单独的文件 `questions/multilingual.jsonl`，字段和 `questions.jsonl` 一样，不要混进第一轮的 100 道。

**怎么跑：和第一轮完全一样**
- 同样的十组、同样的模型、同样的提示词、同样的工具，最多搜 5 次，不抓网页。这样两轮的结果才能比。
- 先试跑：每组 6 道（每种语言 1 道），检查非拉丁文字的编码、搜索工具和判分都正常，再跑全量。

**判分**
- 和第一轮一样，三个 AI 投票：Claude、DeepSeek，再加一个独立的 AI。判分时提醒它们：回答用什么语言不影响对错，只看是否与标准答案或别名一致。
- 这些语言没法人工复核。三票里没有两票一致的，标“待核”，并附上题目自带的来源网址；不要硬判。MSQA 论文报告，它们用的 AI 判分与人工判分一致率是 98%（判分模型不同，只作参考）。

**分析**
- 准确率、搜了比不搜多答对多少、两家搜索的配对比较（McNemar）、耗时、搜索次数、返回的资料量、费用，口径都和第一轮一样。
- 运行中用户新增：多次搜索展示并扣分，选定额外每次扣5分。答对100分，首次不扣，第二至五次依次95/90/85/80；答错0分，不搜索答对100分。待核给区间，原正确率与二元McNemar保留；连续扣分后得分另给按题bootstrap，不当事前指标。展示每题查询、每次实际返回/摘要、0–5次分布、尝试与超限/参数拒绝。次数是可见搜索工具调用，不推算原生搜索内部改写/分发请求。
- 单独报告每种语言的结果，但每种只有 20 道，只看得出很大的差别；正式的比较看 6 种语言合起来的 120 道。
- 和第一轮放在一起看：两家搜索的差距，在中文、英文上和在这 6 种语言上，是否不一样。
- 单独写一份报告，不改第一轮的数字。

**结果存放和开源**
- 跑的时候写进 `tmp/archive-multilingual/`，结构和 `tmp/archive/` 一样；十组全部跑完、判完分，再移到 `results/<跑的日期>-multilingual/`。试跑的输出放 `tmp/pilot-multilingual/`。
- MSQA 是 CC BY 4.0，可以并进我们的数据部分（CC BY-NC-SA 4.0），但要在 `NOTICE` 里写明出处和原授权。

**这一轮不做的**
- [MultiLoKo](https://github.com/facebookresearch/multiloko)（Meta，30 种语言）：它能拿当地语言和英文各问一次同一个知识点，从而分清“不懂这门语言”和“索引里没有”。但它要申请才能下载，并请求不要转载题目，和我们开源原始输出的计划冲突，所以这一轮不用。
- “四个模型不搜都答错的题”（难题档）：先不做；MSQA 的题模型本来就大多不会。
